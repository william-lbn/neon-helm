# Security policy

Do not publish credentials or exploitable sensitive details in a public issue.
Use GitHub's private vulnerability reporting for this repository when enabled,
or contact the repository owner privately. Provide affected version, reproduction
and a proposed mitigation without live secrets. Keep sensitive evidence private.

The initial release is laboratory-qualified only. Review the production gates
before exposing any service outside a trusted lab. This repository owns chart
packaging; runtime vulnerabilities should also be reported to their upstream
and the owning fork. A digest lock ensures reproducibility, not patch currency.
