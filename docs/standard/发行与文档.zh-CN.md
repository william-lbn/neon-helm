# 发行一致性与中文文档

维护分支是研发入口；部署单位是不可变发行。Neon 组合发行必须同时固定 Autoscaling、Control Plane、Helm、PG17、PG18 的源码提交和可复用工作流。`ci/distribution.json` 与 `.github/workflows/dsga-release.yml` 必须一致，不能只更新其中一处。

标准站点包进一步记录 Helm 源码、控制面 Chart 来源、Host 核验工具 SDK 与真实测试、所带二进制摘要、包内文件清单。镜像以独立摘要为准；推送到目标内网仓库后必须先确认摘要，再安装或升级。发行模板中的 `registry.invalid` 是不能作为真实仓库使用的占位符。

源码提交、镜像构建、GitHub CI、Harbor 发布、现场部署、端到端验收是不同事实。旧镜像的构建基线及补丁来源不能改写成后来提交 SHA；当前沿用镜像时应保留原来源和已知限制。仅文档与部署工具变化不要求重编译未变的 PostgreSQL、内核或数据面二进制。

## 当前文档与历史原件

当前部署入口是本目录的中文手册、架构、运维和发行说明。各仓库根 README 介绍当前职责与边界。旧部署入口改为中文导引，旧默认桥接架构图从当前入口清除；详细清理清单单列保留。

有签名、摘要、原始操作或测试依赖的历史验收材料保持原字节，以免破坏证据。上游协议细节和原作者源码注释作为兼容性参考，不能冒充本分支已验收功能。法律许可、机器字段、协议枚举、错误码和 API 路径保留其合同形式。新增面向操作者的解释使用中文。

## 尚未完成的扩展

新 Node 连续接入按用户要求暂缓；生产 HA、完整 TLS、备份灾备、外部 S3、其他硬件及运行规格资格、可选产品全套验收不在本轮范围。Root 初次 HTTP 异常细分归因与自动可信恢复仍需研发。4 项未提供的私有 journal fixture 不能算作通过。上述边界不得从 README 删除后变成隐含的完成承诺。

## 已确认的历史控制面差异

当前 PG17/PG18 的公开创建先进入受支持大版本的 DSGA Driver，使用可信运行时目录中的区域，不经过旧 PG16 创建分支。源码中的旧 PG16 分支仍有 rke2-lab 默认区域与固定筛选；它不属于当前标准验收入口，不应向用户宣传为通用部署路径。

capabilities 返回体的 cluster_id 仍是旧实验标签，属于显示元数据，不是本次部署绑定的 Kubernetes 集群 UID，也不是资源安全准入身份。后续应改为显式站点身份并重建控制面验证；本轮部署工具已独立绑定真实 kube-system Namespace UID，不能使用该显示字段替代。这个遗留问题与自动可信恢复状态机均保留为后续控制面研发项。
