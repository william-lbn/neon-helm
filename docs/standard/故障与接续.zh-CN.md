# 故障诊断与原操作接续

先确认原意图、原对象和原结果，再采取对应动作。客户端超时只表示未收到确认，不表示 Kubernetes、数据库、Guest 或仓库没有执行。

```bash
python3 -B tools/standard-site.py inspect --site /secure/site-config/site.json --state /secure/site-install
python3 -B tools/standard-doctor.py --site /secure/site-config/site.json --state /secure/site-install
```

`inspect` 离线读取原收据，不创建目录、不调用集群、不重写文件。`standard-doctor` 仅查询集群 UID、完整输入、选定 release、工作负载就绪、原 Node UID 和声明的镜像摘要；它不会开放准入，也不能替代业务 SQL、Host SDK 或物理内存验收。历史收据缺少完整锁时明确告警，仅可观察。

新操作锁定主 JSON、引用 values、运行时目录、所选 Chart 全树、执行工具、包内二进制和声明的仓库 CA。每阶段变更前重新检查这些内容与 `kube-system` Namespace UID。输入变化或 kubeconfig 指向另一个集群时停止，不能把原状态目录交给新发行继续。凭据不写入公开锁文件。状态目录必须由当前操作者独占，权限 0700；符号链接不能绕过此检查。

| 现象 | 处理边界 |
| --- | --- |
| ImagePullBackOff | 查询原 Pod 事件，检查仓库镜像摘要、节点 CA/拉取权限；不能以某节点缓存存在代替仓库检查 |
| 首次 Host 未就绪 | 查实际 KVM、节点筛选、普通 Pod 与 init container 硬限、原 Lease 与预算 CAS；不扩大授权或填假容量 |
| Helm 原生进程明确失败 | 核对原 history、冻结 values、原进程退出和对象；只有已声明的 `reconcile-helm` 边界允许建立新 revision |
| Helm 或写接口结果未知 | 保留原状态，观察原操作；不换目录、UID 或幂等键重发 |
| Root 状态读取未确认 | 保持关闭准入，确认原实例、Owner、预算、WAL 与原关闭原因后走已有授权恢复协议 |
| 输入或集群 UID 变化 | 停止原操作；不能修改原收据来制造匹配 |

Root 未确认时关闭准入是必要的安全行为。可靠性整改应细分安全诊断、保全原身份并完善受控恢复；不能因下一次健康读成功就无条件重新开放。自动可信恢复状态机及最初 HTTP 异常的细分归因仍是研发事项。当前不宣称已完成它们。

正式卸载按公开业务退役、停止生产者和容量写入者、原 Host 停域、普通 Pod 保护交回、Helm 逆依赖卸载、原 PVC/PV/Node UID 条件擦除、共享平台核验执行。数据擦除是不可逆操作，只能用于操作者明确指定的独占站点和存储根目录。原清理目录失败时观察原回执，不从头重跑 shell 包装器。

历史收据继续由原验收包和原工具管理；新工具不自动升级历史收据。新发行采用新站点配置和新状态目录，经原站点完成正式清理后重新安装。
