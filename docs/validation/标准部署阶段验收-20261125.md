# 通用 Helm 标准部署阶段验收


验收日期：2026 年 11 月 25 日。原始事件时间保留 UTC；本说明按北京时间归档。本轮标准部署、原生控制面和 PostgreSQL 17/18 端到端验收作为同一项交付，逐项结果见同目录机器可读的验收记录。

## 当前可采用的标准

采用分层方案：平台层提供 Kubernetes、CNI、KVM、合格节点运行时、存储类和镜像仓库；发行层固定源码、镜像摘要和执行工具；站点层显式输入仓库、命名空间、地域、存储、节点选择和系统预算；Helm 管理微服务，原生控制面与节点 Owner 管理 Compute 身份、预算及生命周期；验收层独立核对 SQL、Guest 物理内存和退出结清。

标准模板不包含本次现场地址、物理 Node UID、运行 Lease UID、Service UID 或凭据。输入生成器在本次安装发现并绑定运行身份。现有物理 Node 的 UID 可以继续使用；新安装的命名空间、Lease、服务和 Compute 必须取得本次创建的身份。系统组件的单实例部署约定与可配置站点参数在分层说明中分别列出。

在满足平台资格、声明镜像已进入目标仓库并准备好站点输入后，产品部署入口为：

```sh
bash neon-standard/tools/standard-up.sh site-input.json site-operation
```

包传输、镜像构建与平台准备属于各自层次。声明镜像在部署前及每次实际渲染时按摘要核验；镜像缺失、仓库认证未确认、输入变化或集群 UID 不一致均阻止继续。公共域名和公网 IP 不属于内网部署前置条件。当前内置对象存储的 HTTP 能力须显式允许；内部 Proxy 的 SQL 验收使用 `verify-full`，HTTP 配置不计为生产完整 TLS 验收。

## 本轮验收链路

首先完成中间站点的受控 Scheduler 升级，保留原 Node、Lease、Origin 和安装输入，记录原失败及只读接续依据。PG17/PG18 均完成控制面创建、各 10,000 行 SQL、原 Compute 自动内存增长与收缩、数据与 WAL 校验、暂停、恢复、恢复后数据复验和正常退役。

随后执行原发布卸载工具的完整八阶段：原范围清点、停止容量写者、结束五个 Host 域、归还普通 Pod 保护、清理主机套接字及网络、卸载九个原 release、物理清除七个原数据卷、核对空场。共享 Kubernetes 平台及 Harbor 保留。命名空间、CRD、Host 账本、普通 Pod 保护、原数据和主机残留均按原身份校验，未使用强制删除 VM 或清空账本代替结清。

空场通过后，使用固定标准包执行一次全新部署，`standard-up.sh` 耗时 **184.281 秒**，全部部署阶段一次完成，五个 Host 首次建账及控制面就绪，体检无失败项。该耗时仅包含产品标准命令，外层包传输和平台准备另计。再用新创建的 PG17/PG18 实例重复完整业务、物理内存和生命周期验收，最终保留已部署系统，验收 Compute 正常退役。

每个版本的物理规格均完成 **7→8→7 GiB**。独立 Root 只读记录确认 Guest 内存实际增加并返回原值；增长和收缩期间 VM UID、Runner Pod UID、Compute 实例及 PostgreSQL 启动标识保持不变。前、中、后数据行数、求和和校验和一致，原 WAL 同时存在增长、收缩及成功结清记录。没有通过手工修改 VM 规格、替换观测数值或放宽策略制造通过。

只读观察与容量动作分离。本轮曾出现一次外部只读请求超时，原错误保留；取得同一原实例稳定基线后才提交 SQL 负载。云端通道中断后，PG18 在尚未提交负载时续建只读观察窗口，保留原窗口记录。部署、创建和已提交的原负载均未重放。

## 已整改的通用问题

- 完整冻结 Chart、values、目录、工具和 kubeconfig 输入，绑定原集群 UID；私有状态采用安全路径、原子写入和独占锁。只读诊断不修改安装事实。
- 首次建账提供显式当前 Kubernetes 快照模式。固定原 Node/Lease UID、预算策略、Profile 和系统保留，每次完整重读后只用本次 Node RV 做 CAS；旧冻结 RV 模式保持原语义。已有、残缺或损坏账本不能重新初始化。
- 共享集群保留的成功、失败普通 Job 不再永久阻断冷安装。仅完整退出、无 VM/迁移 Owner、无本系统原生保护及来源的候选，重读同一 UID/RV 和退出证据后才可排除。运行期及插件事件还须确认原账本无 Placement/Hold；已有持有继续原退休协议。没有按现场 Pod 名称或命名空间豁免。
- 静态 Pod 要求 kubelet 已确认的实际资源和运行状态，阻止仅修改 API 镜像 spec 而进程仍无硬限的虚假证明。现场两个 kube-proxy 的原生配置漂移已修复，节点配置属于平台层，未写入产品模板。
- 支持未开放控制面时的部分安装安全退出，并修正原命名空间已完成删除后的空场核验及失败构造锁清理。原失败回执、原工具和未知结果均保留，不从头重放未知变更。
- 镜像来源、维护源码、组合发行锁、实际仓库摘要和验收物料分别记录；关键说明、当前 README、架构、运维与维护入口采用中文，失效入口及旧图清理或明确标记为历史资料。

## 未纳入能力和后续改进

| 项目 | 当前边界与影响 | 后续要求 |
| --- | --- | --- |
| 新增物理 Node 热接入 | 所有者暂缓；本次审批的 Host 域仍是固定身份与预算快照，不能宣称新 Node 已自动获得执行资格 | 提供新节点后，验收受控发现、新域及原 Lease 创建、镜像与 KVM 资格、实际 Compute 调度、扩缩容和失败退出 |
| Root 读取未知后的可信恢复 | 未确认读取时禁止新授权、保留原持有是安全边界；不能用一次健康读无条件打开准入 | 后续完善基于原实例、Owner、原关闭原因、预算和原关闭选择器的可信恢复；任何未知写仍只读观察原结果 |
| PG16 兼容路径与展示标签 | 控制面保留的旧 PG16 创建路径仍有历史环境默认值，`capabilities.cluster_id` 仍有历史展示标签；当前 PG17/PG18 原生路径不经过旧创建分支 | 纳入其他版本产品前移除默认环境假设并另行验收，展示身份与真正的集群 UID 清楚区分 |
| 组合 CI 的构建范围与耗时 | 维护分支 Push 当前会触发串行完整候选发行，包含旧版本构建；文档归档也可能触发昂贵任务。源码门禁、镜像构建、公开候选发布和内网实际发行须分别看待 | 后续增加受验证的文档变更分类、按制品依赖选择构建矩阵和缓存；保留进行中候选的原镜像写入及回执，不能取消后伪称已发布 |
| 生产 HA、完整 TLS、备份灾备 | 按所有者确认不在本轮验收范围；内网条件和实验 HTTP Profile 不等于这些生产能力通过 | 单独制定拓扑、信任、故障注入、备份恢复及灾难演练计划 |

## 资料使用

最终判定同时依据本目录验收 JSON、原始私有证明、固定包摘要以及对应提交的 CI。源码测试成功不替代现场 SQL、真实物理内存和生命周期结果；中间升级接续成功也不替代本轮全新一键部署。
